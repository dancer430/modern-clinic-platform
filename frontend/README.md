# Frontend (Vue 3 Admin Console)

Vue 3 + TypeScript + Vite admin console for the Medical Booking
Platform. Talks to the Django API at `http://127.0.0.1:8000` (via the
Vite dev proxy in dev, via the bundled nginx in the Docker image).

The Docker path is the recommended way to run the full stack — see the
root [`README.md`](../README.md). This document covers the **local
non-Docker** workflow and the day-to-day operations on the frontend
codebase.

## Directory Map

| Path | Responsibility |
|------|---|
| `src/main.ts` | App entry. Mounts the root component, installs Pinia, the router, and Element Plus. |
| `src/App.vue` | Root layout shell. |
| `src/router/` | Vue Router config and route guards. `__tests__/` covers role-aware guards. |
| `src/features/` | Vertical feature modules — each owns its own API client, components, pages, composables, types, and tests. Currently `appointments/` and `auth/`. New features should follow this boundary. |
| `src/views/` | Page-level views that have not yet been migrated into `features/` (Dashboard, Doctors, Patients, Profile, Records, TimeSlots, Login). The active refactor is moving these into the feature structure. |
| `src/shared/http/` | Axios instance, token-refresh interceptor, and the uniform error envelope adapter. Imported by every feature's `api.ts`. |
| `src/components/` | Cross-feature UI primitives (currently `BrandLogo.vue`). |
| `src/composables/` | Cross-feature composition functions (currently `usePlatformBrand.ts`). |
| `src/utils/` | Pure helpers with no Vue dependency (currently `imageUtils.ts` for avatar / attachment compression). |
| `src/assets/`, `src/style.css` | Static assets and global styles. |
| `src/env.d.ts` | TS shims for Vite env vars. |
| `auto-imports.d.ts` | Generated by `unplugin-auto-import` — do not edit by hand. |
| `components.d.ts` | Generated by `unplugin-vue-components` — do not edit by hand. |
| `vite.config.ts` | Build config: `@/*` alias for `src/*`, Element Plus auto-import, dev proxy `/api → http://localhost:8000`. |
| `nginx.conf` | Used only by the production Docker image to serve the built `dist/`. |

## Local Dev

```bash
cd frontend
npm install
npm run dev   # Vite dev server on http://127.0.0.1:5173
```

The dev server proxies `/api/*` to `http://localhost:8000`, so you need
the backend running locally (or in Docker with port 8000 published).

## Docker Dev

The full stack runs from the repository root with `sh ./init-stack.sh`.
The frontend container builds the Vue app and serves the static bundle
through nginx on port 80, exposed on the host as 5173. See root
[`README.md`](../README.md) and [`docs/setup.md`](../docs/setup.md).

## Tests, Typecheck, Build

| Command | Purpose |
|---|---|
| `npm run test` | Vitest in watch mode. |
| `npm run test:run` | Vitest one-shot. Used by CI. |
| `npm run test:run -- src/path/to/file.spec.ts` | Run a single test file. |
| `npm run typecheck` | `vue-tsc -b --noEmit`. |
| `npm run build` | `vue-tsc -b` then `vite build` → `dist/`. |
| `npm run preview` | Serve the built `dist/` locally for smoke-testing. |

CI runs `npm run test:run` and `npm run build`. See
`.github/workflows/ci.yml`.

## Conventions

- **Feature boundaries**: every feature lives in `src/features/<name>/`
  with its own `api/`, `pages/`, `components/`, `composables/`,
  `types.ts`, and `__tests__/`. Cross-feature reuse goes through
  `src/shared/`, `src/components/`, `src/composables/`, or
  `src/utils/`. The migration plan is in
  [`openspec/changes/standardize-frontend-feature-boundaries/`](../openspec/changes/standardize-frontend-feature-boundaries/)
  and [`openspec/changes/migrate-remaining-pages-to-features/`](../openspec/changes/migrate-remaining-pages-to-features/).
- **HTTP and auth**: never call `axios` directly in a feature — import
  the configured client from `src/shared/http/`. It owns the
  `Authorization` header, the JWT refresh flow, the uniform error
  envelope, and the logout-on-401 trigger. Background:
  [`openspec/changes/unify-auth-client-responsibilities/`](../openspec/changes/unify-auth-client-responsibilities/).
- **Auto-imports**: Element Plus components and common Vue/Pinia APIs
  are auto-imported. The two `*.d.ts` files in this directory are
  regenerated on build — commit them when they change so type-checking
  passes in CI.

## Debugging

- **Vite dev proxy**: if API calls 404, confirm the backend is on
  `http://localhost:8000` (or update the proxy target in
  `vite.config.ts`).
- **Token-refresh path**: clear `localStorage` in DevTools and reload
  to reproduce the unauthenticated → login redirect, or expire the
  access token by editing it.
- **Element Plus components missing styles**: usually the auto-import
  resolver was bypassed by a manual `import` — let
  `unplugin-vue-components` resolve it instead, or add an explicit
  style import.
- **Build fails with TS errors but tests pass**: `vue-tsc` is stricter
  than the IDE in some cases; run `npm run typecheck` locally before
  pushing.
